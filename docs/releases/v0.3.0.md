A release about the traffic graph, and a fix everyone on a real device needs: v0.2.0 hung on a
black screen after picking an app. Nothing changed on the phone's side, so apps built with the
v0.1.0 library work with this release.

## Fixed

- **The first frame of a device session no longer hangs.** In v0.2.0, picking an app in the
  picker left a black screen for tens of seconds while the smooth graph drew an empty time
  window at a nanosecond per column, building gigabytes of data; closing the window to escape it
  left mouse reporting switched on in the shell. The columns' width now comes from the zoom, and
  that frame takes a millisecond. The same hang could hit `traffic-police demo` when its first
  frame came before its first traffic.
- Terminal.app showed the image probe's question (`Gi=31,…`) in the corner of the first screen.

## New

- **Receiving above, sending below.** The two series mirror each other around a zero line, each
  half scaled to its own peak, so a few KB/s received stays readable next to hundreds of KB/s
  sent (on one shared scale it was a flat line along the bottom). The top of each scale is
  labelled in its series' color. `[ui] graph_layout = "overlay"` (or `:` → layout) keeps the old
  look, both above one baseline on one scale, as Android Studio draws it.
- **Solid areas.** The default style fills the graph from the zero line to the value with block
  characters, the edge in eighths of a row and no gaps, each row shaded from dim at the zero line
  to full color at the peaks. The braille curves of v0.2.0 are the `curves` style; `smooth` is
  the areas. The hanging half's partial blocks come from a newer Unicode block that Cascadia
  Code, the Nerd Fonts and Iosevka have and Menlo and SF Mono do not: if that half shows boxes,
  set `[colors] background` to your terminal's background color and it is drawn with the blocks
  every font has.
- **A second of smoothing.** Curves and edges are averaged over a second (Android Studio's time
  base for rates) instead of half of one, so polls a second apart become waves instead of bumps.
  `[ui] graph_smoothing` sets it, from 0.5 to 5 seconds; the live edge trails a little more with
  a wider window.
- The y scale's steps go 1, 1.5, 2, 3, 4, 6, 8, 12 … instead of doubling, so a curve is never
  drawn under half of its axis.

## Changed

- `graph_style = "smooth"` now means the solid areas; `curves` is the braille curves it used to
  mean. `area` and `solid` are accepted and mean the areas. The graph's default is the mirror
  layout; the style and layout commands are in the `:` palette.
- A taller graph suits the mirror: each half gets half the rows. `graph_height = 16` in
  `[ui]` gives each half seven rows.

## Compatible with v0.1.0 and v0.2.0

The Android library and the attach agent are unchanged (still 0.1.0), and so is the protocol
between them and this program. Apps built with the v0.1.0 library and session files saved by
earlier versions work with this release, and its session files open in them. A `config.toml`
from an earlier version keeps working; the settings it doesn't name take their new defaults.

## Downloads

| File | For |
|---|---|
| `traffic-police-macos-arm64` | macOS on Apple silicon |
| `traffic-police-linux-x86_64` | Linux on x86_64 with glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12, Fedora 35 and later) |
| `traffic-police-windows-x86_64.exe` | Windows 10 and 11 on x86_64 |

`SHA256SUMS.txt` has their checksums, `LICENSE` is the Apache License 2.0, and
`THIRD-PARTY-LICENSES.txt` lists the licenses of what the binaries contain.

You also need adb (Android SDK platform-tools), and a device or emulator with Android 8.0 (API 26)
or newer. The binaries are not code-signed. On macOS and Linux make the file executable
(`chmod +x`); macOS then refuses a downloaded file from an unidentified developer until you run
`xattr -d com.apple.quarantine traffic-police-macos-arm64`. Windows may warn that the publisher is
unknown.

## Known limits

- The phone's side is the same as in v0.1.0, which was tried on emulators at Android 8.0, 12, 16
  and 17 (API 26, 31, 36 and 37), and in library mode also on a phone with Android 16. Attaching
  at launch on Android 8.1 to 10 has not been tried on a device.
- Not captured: WebSocket messages, Cronet, WebView, native sockets, and an OkHttp whose names a
  minified debug build changed (`doctor` shows the hooks' status).
