traffic-police now shows the device's log beside the app's traffic, as Android Studio's Logcat
does: **Logdawg**, view `4`. It also switches to another app without quitting.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/git-krishnabisht/traffic-police/master/install.sh | sh
```

On Windows, in PowerShell:
`irm https://raw.githubusercontent.com/git-krishnabisht/traffic-police/master/install.ps1 | iex`.
The installer takes the file for your system from this page, checks it against `SHA256SUMS.txt`,
puts it in `~/.local/bin` (on Windows `%LOCALAPPDATA%\Programs\traffic-police`) and adds that
folder to your PATH; running it again updates. The README's Install section has the options.

## New

- **Logdawg, the device's log** (press `4`). The log is read over adb, as `logcat` reads it, in
  library, attach and flutter mode, and the app needs nothing for it. It shows on the same
  timeline as the requests and starts with your app's lines (`package:mine`: every line of the
  app's user id, from all its processes and across restarts). Everything the device still keeps
  from before the session comes first, so after `:q` a new run shows the app's earlier lines
  again. A message of several lines, a stack trace say, stays one entry. `Enter` opens a line,
  `y` copies it as `logcat -v threadtime` prints it, `F` freezes the view, `x` clears the log
  (the requests stay) and `t` switches the clock.
- **Android Studio's filter language** (`/` in view 4), as Studio's own parser reads it: `tag:`,
  `package:` and `process:`, `message:`, `line:`, `level:`, `is:crash`, `is:stacktrace`,
  `is:error` (that level exactly), `age:`, and also `pid:`, `tid:`, `uid:` and `/regex/`. `-`
  rules a term out, `=:` matches exactly and `~:` by a regex; `|`, `&` and parentheses combine
  terms, and terms with the same key are alternatives. A filter that does not parse is marked
  where it breaks.
- **Pause the log**: `Space` in view 4 stops reading the log; `Space` again carries on with what
  the device logged meanwhile. In views 1 to 3 `Space` still pauses the network capture.
- **A request's Logs tab** (its fifth): the app's log lines while the request ran, with `▶` on
  the lines of the thread that made it. The Call Stack tab shows that thread's kernel id (the
  `tid` logcat shows).
- **Requests among the log's lines**: a `⇄ request` row at each request's start in view 4, with
  its method, status, time and URL. `Enter` opens it in view 1, `y` copies it as cURL, and `R`
  hides and shows them.
- **The graph's range** (`v`) filters view 4 too: the lines in it and the requests that overlap
  it.
- **Session files keep the log**: a session saved with `e` includes the device's log (with some
  requests, the lines of their time), and `open` shows it in view 4.
- **Another app without quitting**: `A` (or `:app`) opens the app picker on the session's
  device. Picking another debuggable app moves the network capture and `package:mine` to it,
  the agent attached when it has no library; what came before stays, marked on the timeline.
- **New settings**: `[logdawg]` with `enabled`, `buffers`, `history` (`"all"`, the default, or a
  number of lines), `keep` (the memory the lines may use, 64 MB unless set), `filter` and
  `requests`; `[ui] view = "logdawg"` and `[ui] tab = "logs"`; and the colors `log-verbose` to
  `log-assert`.

## Compatible with earlier versions

The protocol between the app and traffic-police is still version 1. The 0.5.0 runtime also sends
each thread's kernel id, which an older traffic-police skips; with an app built with an older
library, the Logs tab marks the main thread's lines only. Session files from earlier versions
open as before (without a log), and an older traffic-police opens a 0.5.0 file without its log.
The attach agent inside the binary is still 0.2.0, with the 0.5.0 runtime. `config.toml` files
from earlier versions keep working. The library is in the Maven repository as 0.5.0:
`debugImplementation("io.trafficpolice:capture:0.5.0")` and
`releaseImplementation("io.trafficpolice:capture-noop:0.5.0")`.

## Downloads

| File | For |
|---|---|
| `traffic-police-macos-arm64` | macOS on Apple silicon |
| `traffic-police-linux-x86_64` | Linux on x86_64 with glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12, Fedora 35 and later) |
| `traffic-police-windows-x86_64.exe` | Windows 10 and 11 on x86_64 |

`SHA256SUMS.txt` has their checksums, `LICENSE` is the Apache License 2.0, and
`THIRD-PARTY-LICENSES.txt` lists the licenses of what the binaries contain.

You also need adb (Android SDK platform-tools), and a device or emulator with Android 8.0 (API 26)
or newer. The binaries are not code-signed. The installer takes care of that; if you download a
file yourself, make it executable (`chmod +x`) on macOS and Linux, and on macOS run
`xattr -d com.apple.quarantine traffic-police-macos-arm64`, since macOS refuses a downloaded file
from an unidentified developer. Windows may warn that the publisher is unknown.

## Known limits

- Logdawg is in the UI only: `tail` and `record` do not read the log.
- The filter does not have Studio's `is:firebase` or its match-case switch (case never matters).
- gRPC in attach mode: calls an app makes with `channel.newCall` on a channel it built before the
  attach are not seen (calls through stubs are).
- WebSockets in attach mode: a socket whose handshake ends before the app's `newWebSocket` call
  returns (only seen with a server in the same process) reaches the app's listener unwrapped, and
  what the app sends through that socket is not captured. Library mode does not have this gap.
- Flutter mode misses requests made before it connected, shows a body once its request has
  ended, and cannot apply rules.
- Not captured: Cronet, WebView, native sockets, and an OkHttp whose names a minified debug build
  changed (`doctor` shows the hooks' status).
- No build for Intel Macs or Linux on ARM yet: build from source (README).
