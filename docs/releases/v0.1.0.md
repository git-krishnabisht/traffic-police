The first release. traffic-police shows an Android app's HTTP and HTTPS traffic in your terminal, the
way Android Studio's Network Inspector does: a live traffic graph, the requests on a timeline, full
headers and bodies, and the thread and call stack that made each request. No proxy and no
certificates: a small runtime inside the app hooks OkHttp and HttpURLConnection.

## Two ways into an app

- **Attach mode:** any debuggable build, with nothing added to the app.
  `traffic-police --mode attach -p com.example.app --launch` restarts the app with the agent loaded,
  so even its first requests are captured (Android 11 and newer; on Android 8.0 the agent attaches
  just after the start). The agent is built into these binaries.
- **Library mode:** add `io.trafficpolice:capture` to the app's debug build. The library is not on a
  Maven repository yet: build it from source (README, "Watch your app").

## Also in it

- Filters, body search and pins; copy as cURL, save a body, export HAR; session files that reopen
  as they were; compare two requests; decode JWTs, base64 and URL encoding; a command palette.
- Rules that delay or fail a request, or change a response's status, headers or body, from
  `.traffic-police/rules.toml`, applied while the app runs.
- Without the UI: `tail` (text or JSON lines), `record`, `export`, and `doctor`, which checks adb,
  the device, the app and attach mode, and says how to fix what is wrong.

## Downloads

| File | For |
|---|---|
| `traffic-police-macos-arm64` | macOS on Apple silicon |
| `traffic-police-linux-x86_64` | Linux on x86_64 with glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12, Fedora 35 and later) |
| `traffic-police-windows-x86_64.exe` | Windows 10 and 11 on x86_64 |

`SHA256SUMS.txt` has their checksums, `LICENSE` is the Apache License 2.0, and
`THIRD-PARTY-LICENSES.txt` lists the licenses of what the binaries contain.

You also need adb (Android SDK platform-tools), and a device or emulator with Android 8.0 (API 26)
or newer. The binaries are not code-signed. On macOS and Linux make the file executable
(`chmod +x`); macOS then refuses a downloaded file from an unidentified developer until you run
`xattr -d com.apple.quarantine traffic-police-macos-arm64`. Windows may warn that the publisher is
unknown.

## Known limits

- Tried on emulators at Android 8.0, 12, 16 and 17 (API 26, 31, 36 and 37); library mode also on a
  phone with Android 16. Attaching at launch on Android 8.1 to 10 has not been tried on a device.
- Not captured: WebSocket messages, Cronet, WebView, native sockets, and an OkHttp whose names a
  minified debug build changed (`doctor` shows the hooks' status).
