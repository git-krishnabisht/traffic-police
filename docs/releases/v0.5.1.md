A small release: what quits is now a setting (`:q`, a key, or both), and the installers download
faster.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/git-krishnabisht/traffic-police/master/install.sh | sh
```

On Windows, in PowerShell:
`irm https://raw.githubusercontent.com/git-krishnabisht/traffic-police/master/install.ps1 | iex`.
The installer takes the file for your system from this page, checks it against `SHA256SUMS.txt`,
puts it in `~/.local/bin` (on Windows `%LOCALAPPDATA%\Programs\traffic-police`) and adds that
folder to your PATH; running it again updates. The README's Install section has the options.

## New

- **What quits is a setting.** `quit` under `[keymap]` takes `":q"`, keys, or both. `":q"` is the
  default and stands for Neovim's quit commands (`:q`, `:q!`, `:qa`, `:wq`, `:x` and the like),
  typed after `:` and run with Enter. `quit = "q"` quits with `q` alone, `quit = ["q", ":q"]`
  with either, and `quit = ["q", "ctrl+c"]` as 0.3.1 and earlier did. Ctrl+C bound to quit quits
  from anywhere, even from a text field. The device and app pickers follow the setting too.
- **Ctrl+C can be bound** to any action, not only to quit.
- A key that does not quit (`q`, Ctrl+C) says what does, as the setting has it, and so do the
  footer, the help (`?`) and the pickers. When `:q` does not quit, the `:` palette leaves Quit
  out, and `:q` says what quits instead.
- Something always quits: when no key is left for quit (`quit = []`, or its only key given to
  another action), `:q` quits all the same.
- A wrong entry is reported with its line and ignored: only quit takes a command, and only one
  that quits, so `copy = ":q"` and `quit = ":w"` are errors.

## Changed

- **`quit = ["q"]` now means `q` alone.** In 0.5.0 it added `q` and `:q` still quit; now `:q`
  quits only when the list has `":q"`. To keep both, write `quit = ["q", ":q"]`. A config without
  `quit` quits with `:q`, as in 0.5.0.
- **The installers download in eight parts at once.** At times GitHub's release servers give each
  connection about 100 KB/s while the same network is much faster elsewhere: on 2026-10-11 the
  binary came at 116 KB/s over one connection and 682 KB/s over eight. When the server sends
  parts and the file has 1 MB or more, both installers now fetch eight parts at once and join
  them, and the checksum checks the whole. When a part fails (in PowerShell after three tries,
  each from where it stopped), or the server sends the whole file instead, the download goes over
  one connection as before. The download's line ends with "over 8 connections" when the parts
  made it. The one-line installers come from the repository, so they have done this since
  2026-10-11.

## Compatible with earlier versions

Nothing changed on the phone's side. The protocol is still version 1, and the Android libraries
0.5.1 are 0.5.0 under a new number (the runtime reports 0.5.1), so an app built with 0.5.0 needs
no update. The attach agent inside the binary is still 0.2.0, with the 0.5.1 runtime. Session
files and `config.toml` files from earlier versions keep working (but see `quit = ["q"]` above).
The library is in the Maven repository as 0.5.1:
`debugImplementation("io.trafficpolice:capture:0.5.1")` and
`releaseImplementation("io.trafficpolice:capture-noop:0.5.1")`.

## Downloads

| File | For |
|---|---|
| `traffic-police-macos-arm64` | macOS on Apple silicon |
| `traffic-police-linux-x86_64` | Linux on x86_64 with glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12, Fedora 35 and later) |
| `traffic-police-windows-x86_64.exe` | Windows 10 and 11 on x86_64 |

`SHA256SUMS.txt` has their checksums, `LICENSE` is the Apache License 2.0, and
`THIRD-PARTY-LICENSES.txt` lists the licenses of what the binaries contain.

You also need adb (Android SDK platform-tools), and a device or emulator with Android 8.0 (API 26)
or newer. The binaries are not code-signed. The installer takes care of that; if you download a
file yourself, make it executable (`chmod +x`) on macOS and Linux, and on macOS run
`xattr -d com.apple.quarantine traffic-police-macos-arm64`, since macOS refuses a downloaded file
from an unidentified developer. Windows may warn that the publisher is unknown.

## Known limits

- Logdawg is in the UI only: `tail` and `record` do not read the log.
- The filter does not have Studio's `is:firebase` or its match-case switch (case never matters).
- gRPC in attach mode: calls an app makes with `channel.newCall` on a channel it built before the
  attach are not seen (calls through stubs are).
- WebSockets in attach mode: a socket whose handshake ends before the app's `newWebSocket` call
  returns (only seen with a server in the same process) reaches the app's listener unwrapped, and
  what the app sends through that socket is not captured. Library mode does not have this gap.
- Flutter mode misses requests made before it connected, shows a body once its request has
  ended, and cannot apply rules.
- Not captured: Cronet, WebView, native sockets, and an OkHttp whose names a minified debug build
  changed (`doctor` shows the hooks' status).
- No build for Intel Macs or Linux on ARM yet: build from source (README).
