A release about the terminal UI: a smooth graph, long lines that wrap instead of being cut off,
the request body next to the response body, half-page keys as in Neovim, and the look and layout
in `config.toml`. Nothing changed on the phone's side, so apps built with the v0.1.0 library work
with this release.

## New

- **A smooth graph.** Traffic is drawn as curves in braille dots instead of square steps. The
  graph scrolls half a character at a time, its newest second no longer drops to zero while the
  app's counters arrive, and the scale glides to a new maximum instead of jumping. The step
  styles are still there (`[ui] graph_style`, or the `:` palette).
- **Long lines wrap** in every box where text is read: the detail tabs (headers, bodies, call
  stacks), the body box, the diff and decoded values, menus and the Rules view. Lists and bars
  stay one line per item, so their columns line up. Search finds a match where a line breaks.
  `[ui] wrap = false` cuts lines at the edge as before.
- **The request body** is on a second tab of the body box, next to the response body: `b`
  switches, and so do `h` and `l` in the body box.
- **Ctrl+D and Ctrl+U** move half a box, as in Neovim (`Ctrl+P` also moves up). `[ui] scroll`
  sets a number of lines instead.
- **Following new requests** starts again with `G` (or `End`, `Ctrl+G`) at the bottom of the
  list, also while a request is open: the open request then moves to each new one.
- **The look and layout in `config.toml`:** borders (rounded, plain, double or thick), any of
  the theme's 24 colors (`[colors]`), the heights of the graph and the body box (0 hides them),
  the space between boxes (`gap`), the width from which the request sits beside the list, the key
  hints, and what the screen starts with: view, tab, body, graph source, sort and collapsed
  repeats. The README lists every setting.
- **The device and process pickers** fill the screen.

## Changed

- In the body box, `h` and `l` switch between the response and the request body. They used to
  fold and unfold the JSON tree; folding is Enter, and `[` `]` for everything.
- The graph style is `smooth` by default (it was `heavy`). While an app is connected, the live
  graph ends one second before "now", where the app's counters have arrived.
- Active tabs are bold instead of underlined. Boxes without focus have white borders in the dark
  palette (they were dark grey). The body box has no ✕; Esc closes the request.
- One blank column separates the request list from the request's boxes (`[ui] gap`), and the
  Time column has more room around it.
- The JSON path of the line under the cursor is on the detail box's bottom border, so it no
  longer covers the box's last row.
- `traffic-police demo` shows a placeholder shop app (`com.example.shop`, its API on
  `http://localhost:8080`).

## Compatible with v0.1.0

The Android library and the attach agent are unchanged (still 0.1.0), and so is the protocol
between them and this program. Apps built with the v0.1.0 library and session files saved by
v0.1.0 work with this release, and its session files open in v0.1.0. A `config.toml` from v0.1.0
keeps working; the settings it doesn't name take their new defaults.

## Downloads

| File | For |
|---|---|
| `traffic-police-macos-arm64` | macOS on Apple silicon |
| `traffic-police-linux-x86_64` | Linux on x86_64 with glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12, Fedora 35 and later) |
| `traffic-police-windows-x86_64.exe` | Windows 10 and 11 on x86_64 |

`SHA256SUMS.txt` has their checksums, `LICENSE` is the Apache License 2.0, and
`THIRD-PARTY-LICENSES.txt` lists the licenses of what the binaries contain.

You also need adb (Android SDK platform-tools), and a device or emulator with Android 8.0 (API 26)
or newer. The binaries are not code-signed. On macOS and Linux make the file executable
(`chmod +x`); macOS then refuses a downloaded file from an unidentified developer until you run
`xattr -d com.apple.quarantine traffic-police-macos-arm64`. Windows may warn that the publisher is
unknown.

## Known limits

- The phone's side is the same as in v0.1.0, which was tried on emulators at Android 8.0, 12, 16
  and 17 (API 26, 31, 36 and 37), and in library mode also on a phone with Android 16. Attaching
  at launch on Android 8.1 to 10 has not been tried on a device.
- Not captured: WebSocket messages, Cronet, WebView, native sockets, and an OkHttp whose names a
  minified debug build changed (`doctor` shows the hooks' status).
